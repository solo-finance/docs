Every organization that participates in a [network](/concepts/governance/networks)
does so in one or more **roles**. The role determines what the organization may
do on that network: read from it, supply data to it, or administer it.

## The three roles

<CardGroup cols={3}>
  <Card title="Querier" icon="magnifying-glass">
    Reads from the network: queries products, records consent, and searches entities.
  </Card>
  <Card title="Furnisher" icon="arrow-up-to-line">
    Everything a querier can do, plus furnishing data into the network and creating querying policies.
  </Card>
  <Card title="Governor" icon="gavel">
    Everything a furnisher can do, plus configuring the network's querying and furnishing policies.
  </Card>
</CardGroup>

The roles build on each other: **any** membership lets your organization query
the network, and a governor can furnish without also holding the furnisher
role.

## What each role permits

### Querier

Any membership on a network — querier, furnisher, or governor — lets your
organization:

- **Record consent** for consumers and businesses in that network — see
  [Consent](/concepts/identity/consent).
- **Search entities** visible to you in that network.
- **Query products and run coverage checks** with the network in
  `network_ids`. A query lists one or more networks, and you need a
  membership on every one of them.
- **Read the network's furnishing policies.**

What a query returns is never determined by the role alone. The
[querying policy](/concepts/governance/querying-policies) decides which
furnished verifications qualify, and [consent](/concepts/identity/consent) and
[entitlement](/concepts/governance/entitlement) decide which records and
fields you can see.

### Furnisher

A furnisher can do everything a querier can, plus:

- **Furnish data** — calls `POST /v1/products/kyc_certificate_snapshot/furnish`
  or `POST /v1/products/kyb_certificate_snapshot/furnish` naming the network,
  or delivers [JSONL files](/api-overview/furnishing/file-upload) from the
  dashboard or over [SFTP](/api-overview/sftp/overview).
- **Create querying policies** in the network, and configure the ones it
  created.

Furnishing is also how an organization earns read access to the subjects it
contributes — see [Entitlement](/concepts/governance/entitlement). A furnisher
never names a furnishing policy: each file record's `_type` routes it to the
network's mappings that claim that type.

### Governor

A governor can do everything a furnisher can, plus:

- **Configure any querying policy** in the network, not just its own.
- **Administer furnishing policies** — assign mappings to the network and
  configure them.

The network's **governor entity** — the organization that created the network
— is the one that manages the participant list (adding and removing members,
changing their roles, deciding join requests) and edits the network's
settings. Other organizations can hold the governor role without being the
governor entity.

A governor seat is not a window into other members' data. Reads by a governor
are filtered by consent and entitlement like anyone else's.

## Role-to-endpoint matrix

The table below shows which memberships each public `/v1` operation requires.
SOLO enforces these checks server-side and refuses a call made without the
required membership; for queries, furnishing, and consent the refusal is
`403 PERMISSION_DENIED`.

| Endpoint | Who can call it |
|---|---|
| `POST /v1/consent/consumer_identity` | Any member of `network_id` |
| `GET /v1/consent/consumer_identity/{consent_id}` | Any member of `network_id` |
| `PUT /v1/consent/consumer_identity/{consent_id}` | Any member of `network_id` |
| `POST /v1/consent/business_identity` | Any member of `network_id` |
| `GET /v1/entities/consumer_identity/search` | Any member of `network_id` |
| `GET /v1/entities/business_identity/search` | Any member of `network_id` |
| `POST /v1/products/kyc_certificate_snapshot/query` (and the other product queries) | Any member of every network in `network_ids` |
| `POST /v1/products/check` (coverage check) | Any member of every network in `network_ids` |
| `POST /v1/products/kyc_certificate_snapshot/furnish` | Furnisher or governor of `network_id` |
| `POST /v1/products/kyb_certificate_snapshot/furnish` | Furnisher or governor of `network_id` |
| `POST /v1/networks/policies/querying` | Furnisher or governor of `network_id` |
| `PUT /v1/networks/policies/querying/{policy_id}/configuration` | The policy's creator, or a governor of the policy's network |
| `GET /v1/networks/policies/furnishing` | Any member of `network_id` |
| `GET /v1/networks/policies/furnishing/{policy_id}` | Any member of `network_id` |
| `POST /v1/institution-attestation-event` | Any authenticated organization; attests for itself and isn't tied to a network |
| `POST /v1/furnishing/mapping/{verify,trace,suggest,propose}` | Any authenticated caller; dry-run only, reads no network data |

## Roles are additive

An organization can hold more than one role on the same network. SOLO records
each role as a separate membership, so removing one role does not affect the
others. The same organization can't hold the same role twice on one network.

## Roles are network-specific

Roles do not transfer between networks. Networks are flat — there are no
parent or child networks — so a role on one network grants nothing on any
other. To participate in several networks, your organization needs a
membership on each.

## Who can change roles

Roles are managed in the dashboard. Only the network's governor entity can add
participants, change their roles, or remove them. Two rules are enforced
server-side:

- **A network always keeps at least one governor.** SOLO rejects any change
  that would leave a network with no governor membership.
- **An organization can always leave.** It can remove its own memberships,
  provided that doesn't remove the network's last governor.

An organization can also join a network itself: an **open** network listed in
the directory admits it as a querier immediately, and any other request waits
for the governor's approval. See
[Joining a network](/concepts/governance/networks#joining-a-network).
