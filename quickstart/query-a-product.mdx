Querying reads consolidated data about an entity from a
[network](/concepts/networks). Because you're reading personal or business data,
you first record [consent](/concepts/consent), then query a product with the
resulting `consent_id`.

## Prerequisites

- An SDK token exported as `SOLO_TOKEN` (see [Quickstart](/quickstart)).
- The **querier** role in a network, and your network's `network_id`.
- A **querying policy** for the product in that network (its `policy_id`). See
  [Policies](/concepts/policies).

## 1. Record consent

Querying a consumer requires consent. Create a consent record with the subject's
identity, confirming you've gathered their permission:

<CodeGroup>

```bash cURL
curl -X POST https://api.solo.one/consent/consumer \
  -H "Authorization: Bearer $SOLO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "network_id": "9f1c0c2e-…",
    "did_gather_consent_from_consumer_prior": true,
    "consumer_consent_identity": {
      "first_name": "Jane",
      "last_name": "Doe",
      "date_of_birth": "1990-01-15",
      "personal_email": "jane@example.com",
      "phone_number": "+14155550100",
      "social_security_number": "123-45-6789"
    }
  }'
```

```python Python
import requests, os

resp = requests.post(
    "https://api.solo.one/consent/consumer",
    headers={"Authorization": f"Bearer {os.environ['SOLO_TOKEN']}"},
    json={
        "network_id": "9f1c0c2e-…",
        "did_gather_consent_from_consumer_prior": True,
        "consumer_consent_identity": {
            "first_name": "Jane",
            "last_name": "Doe",
            "date_of_birth": "1990-01-15",
            "personal_email": "jane@example.com",
            "phone_number": "+14155550100",
            "social_security_number": "123-45-6789",
        },
    },
)
consent_id = resp.json()["consent_id"]
```

```javascript JavaScript
const resp = await fetch("https://api.solo.one/consent/consumer", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.SOLO_TOKEN}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    network_id: "9f1c0c2e-…",
    did_gather_consent_from_consumer_prior: true,
    consumer_consent_identity: {
      first_name: "Jane",
      last_name: "Doe",
      date_of_birth: "1990-01-15",
      personal_email: "jane@example.com",
      phone_number: "+14155550100",
      social_security_number: "123-45-6789",
    },
  }),
});
const { consent_id } = await resp.json();
```

</CodeGroup>

The response contains a `consent_id`. Reuse it for every query of this subject
while the consent is valid.

<Warning>
  Only set `did_gather_consent_from_consumer_prior` to `true` if you have actually
  obtained the consumer's permission. It is an attestation.
</Warning>

## 2. Query the product

Pass the `consent_id` and the network + policy scope to the product's query
endpoint. (The Python and JavaScript snippets continue the script from step 1,
reusing the `consent_id` you captured.)

<CodeGroup>

```bash cURL
curl -X POST https://api.solo.one/products/kyc_certificate/query \
  -H "Authorization: Bearer $SOLO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "consent_id": "a3f0b9c7-…",
    "network_policy": [
      { "network_id": "9f1c0c2e-…", "policy_id": "5e7d2a14-…" }
    ]
  }'
```

```python Python
resp = requests.post(
    "https://api.solo.one/products/kyc_certificate/query",
    headers={"Authorization": f"Bearer {os.environ['SOLO_TOKEN']}"},
    json={
        "consent_id": consent_id,
        "network_policy": [
            {"network_id": "9f1c0c2e-…", "policy_id": "5e7d2a14-…"}
        ],
    },
)
print(resp.json())
```

```javascript JavaScript
const result = await fetch("https://api.solo.one/products/kyc_certificate/query", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.SOLO_TOKEN}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    consent_id,
    network_policy: [{ network_id: "9f1c0c2e-…", policy_id: "5e7d2a14-…" }],
  }),
});
console.log(await result.json());
```

</CodeGroup>

## 3. Read the result

A `200 OK` returns a **consolidated** view of the subject, limited to the fields
you are [entitled](/concepts/entitlement) to read and what the network's querying
[policy](/concepts/policies) permits.

<Note>
  If a field you expected is missing, it's usually because you haven't earned
  entitlement to it (you've neither furnished nor previously queried it) or the
  policy doesn't expose it in this network.
</Note>
