description: 'Screening against bad actor listings within a sponsor bank network'

The **Bank-Specific Bad Actor List** is a sponsor-bank-scoped list of specific
individuals who, as prior customers of one or more of the bank's fintech
partners, violated one or more documented bank policies. It answers a narrow
question (*has an institution in this network placed this consumer on its bad
actor list?*) and returns a listing indicator plus the details of the most
recent listing. It never issues a reusable certificate; it is a point-in-time
check.

| | |
|---|---|
| **Category** | Fraud & Financial Crime |
| **Use case** | Bad actor screening |
| **Subject** | Consumer |
| **Family** | List (query-only) |
| **Scope** | Listings furnished to the networks in your request's `network_ids` |
| **Operation** | `POST /v1/products/bank_specific_bad_actor_list/query` |

The list is designed to be offered inside a single sponsor bank's network, so a
consumer listed in Bank A's network is not visible to a query that only names
Bank B's network. Listings are contributed by participating institutions
through the [furnishing pipeline](/api-overview/furnishing/overview); there is
no `/furnish` endpoint for this product.

## At a glance

```bash
curl -X POST https://api.sandbox.solo.one/v1/products/bank_specific_bad_actor_list/query \
  -H "Authorization: Bearer $SOLO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "consent_id": "a3f0b9c7-…",
    "network_ids": ["9f1c0c2e-…"]
  }'
```

```json
{
  "provenance_event_id": "7b2d9c4e-…",
  "consumer_identity_id": "c2a4e8d0-…",
  "is_listed": false,
  "furnishing_entity_id": null,
  "furnishing_entity_name": null,
  "bad_actor_reason_code": null,
  "bad_actor_reason_definition": null,
  "bad_actor_list_placement_date": null
}
```

A clean result is `"is_listed": false` (always `200 OK`, never `204`). When any
listing for the consumer is visible in the queried networks, `is_listed` is
`true` and the detail fields describe the most recent listing: who placed it,
the reason code (`account_abuse`, `fraud`, or `policy_violation`), the bank's
definition of the violated policy, and the placement date.

## Identifying the subject

The subject is identified only by your [consent](/concepts/identity/consent)
(`consent_id`) or a direct `consumer_identity_id`. You don't send SSN, date of
birth, or other identifying attributes on the query.
