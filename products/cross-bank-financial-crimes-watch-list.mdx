The **314(b) Cross-Bank Financial Crimes Watch List** is a list shared across
participating banks, beyond a single sponsor-bank network, for suspected
financial-crimes activity. It answers a narrow question (*has a participating
bank reported suspected financial-crimes activity for this consumer?*) and
returns a listing indicator plus the details of the most recent report. It
never issues a reusable certificate.

| | |
|---|---|
| **Category** | Fraud & Financial Crime |
| **Use case** | Watch list screening |
| **Subject** | Consumer |
| **Family** | List (query-only) |
| **Scope** | Reports furnished to the networks in your request's `network_ids` |
| **Operation** | `POST /v1/products/cross_bank_financial_crimes_watch_list/query` |

Unlike the [Bank-Specific Bad Actor List](/products/bank-specific-bad-actor-list),
this list is designed to be offered in a network shared by several banks, so
activity reported by one participating bank is visible to the others in that
network. Reports are contributed by participating banks through the
[furnishing pipeline](/api-overview/furnishing/overview); there is no
`/furnish` endpoint for this product.

<Note>
  Participation in the watch list is intended for financial institutions that
  have filed a 314(b) notice with FinCEN. Each participant is responsible for
  its own regulatory obligations, including how it shares, uses, and acts on
  the information.
</Note>

## At a glance

```bash
curl -X POST https://api.sandbox.solo.one/v1/products/cross_bank_financial_crimes_watch_list/query \
  -H "Authorization: Bearer $SOLO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "consent_id": "a3f0b9c7-…",
    "network_ids": ["9f1c0c2e-…"]
  }'
```

```json
{
  "provenance_event_id": "7b2d9c4e-…",
  "consumer_identity_id": "c2a4e8d0-…",
  "is_listed": false,
  "furnishing_entity_id": null,
  "furnishing_entity_name": null,
  "event_date": null,
  "event_category": null,
  "signal_level": null
}
```

A clean result is `"is_listed": false` (always `200 OK`, never `204`). When any
report for the consumer is visible in the queried networks, `is_listed` is
`true` and the detail fields describe the most recent report: who reported it,
the event date, the category (`money_laundering`, `terrorist_financing`, or
`fraud`), and the signal level (`high`, `medium`, or `low`).

## Identifying the subject

The subject is identified only by your [consent](/concepts/identity/consent)
(`consent_id`) or a direct `consumer_identity_id`. You don't send SSN, date of
birth, or other identifying attributes on the query.

<Warning>
  A listing reflects what a participating bank reported. It is a screening
  input, not a determination. Route hits to your compliance review process;
  decisions based on a listing are your institution's.
</Warning>
